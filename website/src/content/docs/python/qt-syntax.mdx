If your hands already know Qt, `blenderui.qtsyntax` lets them keep typing: `QApplication`, `QWidget`, `QVBoxLayout`, `clicked.connect(...)`. BUI runs that code on its own C runtime and draws it with Blender's widgets. **Neither Qt nor PySide is needed.**

<Callout type="warning" title="Status: partial">
The everyday subset on this page works and is tested. Counted against Qt's own headers (by `tools/qt_coverage.py`), **57%** of the public methods, signals and slots on the 36 core widget classes exist, 37% across all of Qt's widget and GUI classes. Anything that isn't there raises `AttributeError`. A few setters are accepted and ignored: window icons, cursors, word wrap, echo mode and the like (`docs/qt.md` lists them). See [what's missing](#whats-missing).
</Callout>

## A first example

```py title="hello_qt.py"
import sys
from blenderui.qtsyntax import (QApplication, QWidget, QVBoxLayout, QSlider,
                                QProgressBar, QPushButton, Qt)

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Hello, Qt syntax")

layout = QVBoxLayout(window)
slider = QSlider(Qt.Horizontal)
slider.setRange(0, 100)
bar = QProgressBar()
slider.valueChanged.connect(bar.setValue)     # signals connect to any callable
quit_button = QPushButton("Quit")
quit_button.clicked.connect(app.quit)
layout.addWidget(slider)
layout.addWidget(bar)
layout.addWidget(quit_button)

window.resize(320, 140)
window.show()
sys.exit(app.exec())
```

The only line that differs from PySide is the import. For a step-by-step build of a fuller form, follow the [Qt tutorial](../../tutorials/first-app-qt/).

## How it maps

There's no Qt underneath. Each piece of Qt maps onto something in BUI:

| Qt | On BUI |
| --- | --- |
| `QWidget` | A node in BUI's C runtime (the **kit**). A subclass that overrides `paintEvent` becomes a kit canvas, and `QPainter` records into its display list. |
| `QVBoxLayout`, `QHBoxLayout` | Tk's packer, ported to C, with Qt's rules: stretch factors, expanding size policies, spacing between items only, margins on top-level layouts only |
| `QGridLayout`, `QFormLayout` | Tk's gridder, ported to C (`setColumnStretch` maps to column weights) |
| Signals | Plain Python objects (`Signal`, also spelled `pyqtSignal`) |
| `QApplication.exec()` | BUI's event loop: a native window (Win32, X11, Cocoa), or a Tk-hosted one with `BUI_HOST=tk` |
| `QTimer`, `QPropertyAnimation` | Window timers; animations step at 120 Hz with easing curves |

## Supported classes

| Area | Classes |
| --- | --- |
| Application | `QApplication` (`exec`, `quit`, `processEvents`, `topLevelWidgets`, `focusWidget`, `activeWindow`, `closeAllWindows`, the default font and palette), `QTimer` (`singleShot`, `start`, `stop`, `timeout`), `QPropertyAnimation`, `QEasingCurve` |
| Windows | `QWidget`, `QMainWindow` (`setCentralWidget`, `menuBar`, `statusBar`), `QDialog` (`exec`, `accept`, `reject`), `QFrame` |
| Layouts | `QVBoxLayout`, `QHBoxLayout` and `QBoxLayout` (directions, `insert*`, `takeAt`, `replaceWidget`, stretch factors, `QSpacerItem`), `QGridLayout` (spans, alignment, row and column stretch and minimum sizes, `itemAtPosition`), `QFormLayout` (`insertRow`, `removeRow`, `labelForField`, `setRowVisible`), `QStackedLayout` |
| Widgets | `QLabel` (text, alignment, pixmap, `setNum`), `QPushButton` (checkable, flat, default, a menu), `QToolButton` (a default action, auto-raise, arrows), `QCheckBox`, `QRadioButton` with `QButtonGroup` (ids, exclusive), `QLineEdit` (validators, `maxLength`, `textChanged`, `returnPressed`, `editingFinished`), `QAbstractSpinBox`, `QTextEdit`, `QPlainTextEdit`, `QSlider`, `QDial`, `QSpinBox`, `QDoubleSpinBox`, `QProgressBar` (format), `QComboBox` (items, data, `currentIndexChanged`) |
| Views | `QListWidget` and `QListWidgetItem`, `QTreeWidget` and `QTreeWidgetItem` (columns, expand), `QTableWidget` and `QTableWidgetItem` |
| Containers | `QTabWidget`, `QGroupBox` (checkable: the contents follow the check), `QFrame` (a Blender box, or a separator line), `QScrollArea`, `QStatusBar` (permanent widgets) |
| Menus | `QMenuBar`, `QMenu` (`addAction(text, slot, shortcut)`, submenus, sections, separators, `popup`), `QAction` (checkable, visible, data, tips, shortcuts bound on its window), `QActionGroup` |
| Painting | `QPainter`, `QPen`, `QBrush`, `QColor`, `QFont`, `QPixmap`, `QImage` |
| Events | Override `mousePressEvent`, `mouseReleaseEvent`, `mouseMoveEvent`, `mouseDoubleClickEvent`, `keyPressEvent`, `keyReleaseEvent`, `wheelEvent`, `enterEvent`, `leaveEvent`, `resizeEvent`, `contextMenuEvent`, `timerEvent`, `closeEvent` and `paintEvent` |
| Values | `Qt` constants (alignment, keys, orientation, check states, window states and flags), `QPoint`, `QSize`, `QRect`, `QMargins`, `QSizePolicy`, `QIcon`, `QFontMetrics`, `QPalette` (Blender's theme colors), `QCursor`, `QScreen`, validators |
| Dates | `QDate`, `QTime`, `QDateTime`, `QDateTimeEdit`, `QDateEdit` and `QTimeEdit` (a Blender number field per section of the format, in an aligned row), `QCalendarWidget` |
| Dialogs | `QDialogButtonBox`, `QMessageBox` and `QInputDialog`, below; `QFileDialog` (`getOpenFileName`, `getOpenFileNames`, `getSaveFileName`, `getExistingDirectory`) shows Blender's File Browser, and `BUI_FILEDIALOG=native` uses the operating system's dialogs |

The member-by-member list is in [`SYNTAX_COVERAGE.md`](https://github.com/ppmpreetham/BUI/blob/main/SYNTAX_COVERAGE.md#qt-syntax-buiqtsyntax).

## Signals

Signals work as in Qt: declare them on a class, `connect` any callable, `emit` to call them.

```py
from blenderui.qtsyntax import QWidget, Signal

class Thermostat(QWidget):
    changed = Signal(float)           # pyqtSignal and Signal_ are the same thing

t = Thermostat()
t.changed.connect(lambda v: print("now", v))
t.changed.connect(print)
t.changed.emit(21.5)
```

- **Slots can take fewer arguments** than the signal sends: `QPushButton.clicked` sends a `bool`, but a slot with no parameters is called with none.
- `disconnect(slot)` removes one slot; `disconnect()` removes them all.
- Programmatic changes go through the kit, so in our testing a `setValue` made **before the window opens** doesn't emit `valueChanged`. Set dependent widgets yourself at startup, or make the change after `show()`.

## Layouts

Layouts behave like Qt's, including the parts people rely on without thinking:

- `addWidget(widget, stretch)` and `addStretch()` share spare space by stretch factor.
- Spacing goes **between** items only, and margins apply to top-level layouts only.
- Line edits, sliders, combo boxes and progress bars expand **horizontally**; text edits, lists, trees, tabs and custom-painted widgets expand **vertically**.
- `QGridLayout.addWidget(w, row, column, rowspan, colspan, alignment)` and `setRowStretch` / `setColumnStretch` work.

## Custom painting

Override `paintEvent` and draw with `QPainter`. On BUI, your drawing is recorded into a display list that BUI redraws for you; call `update()` when your data changes.

```py title="gauge.py"
import sys
from blenderui.qtsyntax import (QApplication, QWidget, QVBoxLayout, QLabel,
                                QPainter, QColor, QPen)

class Gauge(QWidget):
    def __init__(self):
        super().__init__()
        self.value = 0.6

    def paintEvent(self, event):
        p = QPainter(self)
        p.setBrush(QColor("#282828"))
        p.drawRoundedRect(0, 0, self.width(), 24, 6, 6)
        p.setBrush(QColor("#4772b3"))
        p.drawRoundedRect(0, 0, int(self.width() * self.value), 24, 6, 6)
        p.setPen(QPen(QColor("white")))
        p.drawText(8, 17, "%d%%" % (self.value * 100))
        p.end()

    def mousePressEvent(self, e):
        self.value = e.x() / max(1, self.width())
        self.update()                  # repaint

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Gauge")
layout = QVBoxLayout(window)
layout.addWidget(QLabel("Click the gauge:"))
layout.addWidget(Gauge())
window.resize(300, 120)
window.show()
sys.exit(app.exec())
```

`QPainter` supports `fillRect`, `drawRect`, `drawRoundedRect`, `drawEllipse`, `drawLine`, `drawPolyline`, `drawPolygon`, `drawPoint`, `drawArc`, `drawPie`, `drawText` and `drawPixmap`, plus `setPen`, `setBrush`, `setFont`, `setOpacity`, `translate`, `save` and `restore`.

## Containers, models and dialogs

Docks, toolbars, splitters and tool boxes are drawn the Blender way, models show in Blender's tree list, and message boxes are real windows:

```python
from bui.qtsyntax import (QMainWindow, QDockWidget, QTreeView, QStandardItemModel,
                          QStandardItem, QMessageBox, Qt)

win = QMainWindow()
win.addToolBar("Main").addAction("Save", save)   # a row of tool buttons
model = QStandardItemModel()
model.setHorizontalHeaderLabels(["Name", "Type"])
model.appendRow([QStandardItem("Cube"), QStandardItem("Mesh")])
tree = QTreeView()
tree.setModel(model)                             # redraws when the model changes
dock = QDockWidget("Outliner")
dock.setWidget(tree)
win.addDockWidget(Qt.LeftDockWidgetArea, dock)   # a Blender panel left of the central widget
if QMessageBox.question(win, "Quit", "Save changes?") == QMessageBox.Yes:
    save()
```

- **Containers:** `QStackedWidget`, `QToolBox` (Blender panels: the Qt API keeps one open, and a click on a header opens or closes that panel on its own, as in Blender), `QSplitter` (region edges you drag), `QToolBar`, `QDockWidget`, `QTabBar`, and `QMainWindow`'s `addToolBar`, `addDockWidget` and `setStatusBar`.
- **Model/view:** `QStandardItemModel`, `QStringListModel`, the abstract models to subclass, `QModelIndex`, `QItemSelectionModel`, and `QListView`, `QTreeView` and `QTableView`. One row is selected at a time, and views don't edit cells.
- **Dialogs:** `QDialogButtonBox` (standard buttons by role), `QMessageBox` built on it with Blender's icons (the static helpers return the button clicked) and `QInputDialog` (`getText`, `getInt`, `getDouble`, `getItem`).
- **Actions and menus:** one `QAction` serves a menu, a tool button and its shortcut, which is bound on the window it's in, as Blender's keymap is. Hidden actions leave their menus, and `QActionGroup` and `QButtonGroup` keep one checked. A checked button is drawn pressed in, as Blender draws a selected button.
- **Windows:** maximized and minimized states, opacity, stay-on-top, minimum and maximum sizes, the `[*]` modified marker in the title, and the three context-menu policies.
- **Core:** `QSettings` (an INI file per application, with Qt's groups and arrays), `QKeySequence`, `QShortcut` (the kit's key bindings) and `QClipboard`.

## Style sheets

`setStyleSheet` understands three things: `color`, `background` (or `background-color`) on containers, and `font-weight: bold`. Everything else is Blender's theme. Qt style sheet selectors and pseudo-states aren't supported; `setPalette` sets a widget's background and text colors.

## What's missing

Being upfront, so you don't find out the hard way:

- **Classes:** `QThread`, `QGraphicsScene`, OpenGL widgets.
- **Widgets:** tristate check boxes and editable combo boxes.
- **Model/view:** delegates, editing inside a view, and selecting more than one row.
- **Docks:** they stay docked (no floating or tabbed docks).
- **Infrastructure:** drag and drop, rich text and stylesheet selectors.
- **Accepted and ignored:** window icons, cursors, word wrap, echo mode and item colors, among others. The [full list](https://github.com/ppmpreetham/BUI/blob/main/docs/qt.md#coverage) is in `docs/qt.md`, and `tools/qt_coverage.py` lists what's missing per class.
