Here's the story of BUI so far, in plain words: what each release gave you, and what's waiting on `main` for the next one. For every detail, read the full [CHANGELOG.md](https://github.com/ppmpreetham/BUI/blob/main/CHANGELOG.md); it follows [Keep a Changelog](https://keepachangelog.com), and versions follow [Semantic Versioning](https://semver.org).

## Coming next

These are on `main` and will ship in the next release; the details are under **Unreleased** in the changelog. Nothing here is on PyPI, crates.io or npm yet.

- **Animation.** One animation engine in the C kit runs GSAP-style timelines (position strings such as `"<"` and `"+=1"`, stagger, repeat, yoyo) and Motion-style springs, for Rust, JavaScript, React, Python, Lua and C. Rust gets `<motion.div>` in `rsx!`; see [Motion](../../rust/motion/) and [Effects and animations](../../rust/effects-and-animations/).
- **Vue.** `@blender-ui/vue` renders Vue 3 single-file components in native windows. See [Vue](../../javascript/vue/).
- **D.** A DUB package with the whole C API, idiomatic wrappers and an HTML, CSS and RSX layer. See [D](../../d/overview/).
- **Video with sound.** A `<video>` now plays its audio track. This changes a default: videos used to be silent, so set `muted` to keep one quiet.
- **Rust conditionals.** An `Option` is an element: `None` draws nothing and `Some(x)` draws `x`, so `{ cond.then(|| <p>"hi"</p>) }` replaces an empty placeholder.
- **Controls in node-editor nodes.** A node can hold a button, a checkbox and a dropdown, as Blender's nodes do.
- **More Qt syntax.** Dock widgets, toolbars, model/view, real dialogs, `QSettings`, dates and a calendar: about 57% of the core widget classes' methods, up from 21%.
- **Windows.** Resizing a window is smoother and renders far fewer frames, and a window that animates for ever no longer ignores the mouse and keyboard.
- **Fixes.** Tailwind `text-sm` line heights and `truncate` now show the `…`; form widgets and overlays paint in the right order in Rust.
- **Editor extensions** for `rsx!` in VS Code and Zed. See [Editor support](../../rust/editor-support/).

## In 0.5.1

Released on 13 November 2026: your own themes, windows that are see-through, panels and pie menus, and Lua on LuaRocks. The details are under **0.5.1** in the changelog.

### Your own themes

A theme file (JSON) adds themes next to Dark and Light. Keys are plain English (`button.background`) or Blender's own names (`user_interface.wcol_regular.inner`), all 782 of them, so a theme exported from Blender loads whole. Colors, fonts, corner radius, borders and shadows can all change, and single values can change at run time. Errors name the line and column. See the theming docs and the Catppuccin example.

### Windows that are see-through, and panels (Linux, Windows, macOS)

`wm "transparent"` gives a window per-pixel alpha on all three systems. On Wayland, `wm "layer"` makes layer-shell windows (a panel, a bar, an overlay) with keyboard interactivity. Rust and JavaScript get window kinds (floating, pop-up and more), a `transparent` option and focus and blur events. Linux windows can also be hidden, shown, made frameless or kept on top.

### Pie menus, as in Blender

Open a pie while a key is held and release the key to pick, as Blender does. Also new: `BK_hit_at` finds the interactive widget under a point, a window reports when it gets or loses the keyboard focus, and `<input live>` reports every keystroke, for a search box or a date field.

### LuaRocks

`luarocks install blenderui`, then `require("bui")`: the rock builds the kit and the Lua module with CMake for Lua 5.4. See the [Lua page](../../lua/overview/).

### Smoother and safer

- Text fields blink their caret like a browser's, and Python text no longer has Blender's drop shadow, which made small text look soft.
- Wayland: no more crash at exit, the first window draws at once, frames copy only what changed, and cursors use the compositor's cursor shapes.
- Rust views are lighter and quicker: one hasher, 136-byte elements, and a display list that changes everywhere redraws only what changed.
- Fixed: closing a pie during its open animation, input methods typing key names, a frame callback that closed its own window, the Lua module that could not be loaded, a macOS link error for the npm runtime, and `bui_version_string()` stuck at 0.1.0.

## In 0.5.0

The biggest release since 0.1.0: faster on Linux, input methods, a Wayland host, Lua, and a lot of polish. It came out on 8 November 2026; the details are under **0.5.0** in the changelog.

### Faster to start on Linux

The GPU renderer no longer makes the first frame wait for the OpenGL driver: the device starts on a worker thread, the first frames draw on the CPU, and the window switches over when the GPU is ready (also when it is idle). Start times drop by 50 to 80 percent: Rust from 169 to 61 ms, JavaScript from 207 to 101 ms, Python components from 216 to 96 ms. The [benchmarks page](../../performance/benchmarks/) has a Linux tab with all the numbers, and Rust compile times too.

### Chinese, Japanese and Korean input (Windows)

Text fields and text areas now work with input methods, ported from Blender's own code: the composition is drawn at the caret, the candidate window follows it, and shortcuts keep working because the input method is on only while you edit text. See [text and fonts](../../concepts/text-and-fonts/).

### Native Wayland windows (experimental)

A Wayland host with the same API as X11, modelled on Blender's. It's used on Wayland sessions that don't ask for the GPU renderer, and `BUI_WINDOW_BACKEND` picks one. See [window hosts](../../concepts/window-hosts/).

### Lua

A `bui-lua` executable and a `bui` module for Lua 5.4, LuaJIT and LuaRocks, with every widget and event, 26 examples and tests, from [seclorum](https://github.com/seclorum). See the [Lua page](../../lua/overview/).

### npm packages for Linux and macOS

`@blender-ui/native` now comes prebuilt for Linux x64 and macOS as well as Windows, one small package per platform, installed automatically. From [concprog](https://github.com/concprog).

### macOS works

Three people have tried the Cocoa host by hand (two Apple Silicon Macs and an Intel one), and it's no longer labelled experimental. See [platforms](../../reference/platforms/).

### Fixed

- Python: an occasional crash when a BUI window and Tk shared a thread.
- Node: when no window could be opened, the app now says why instead of running silently.
- CSS: `color-mix()` keeps the other color's hue for white, grays and black (from HEOJUNFO).
- Building BUI as a CMake subproject, and a debug link error (from giraldeau and concprog).

### Thanks

seclorum, concprog, HEOJUNFO, giraldeau, YuFu-Onship, piaoboo and DanNoby, and everyone who tested and reported on Discord.

## From 0.1.0 to 0.4.1

These changes shipped between 0.1.0 and 0.4.1; the changelog lists them by version.

### Closer to Blender 5.x

The biggest theme: BUI now looks and feels even more like the real thing.

- **Text rendered like Blender's.** BUI vendors FreeType 2.13.3 and renders text as Blender's BLF does: light hinting, Blender's gamma, Inter's optical size, true bold and Blender's text shadows. [Text and fonts](../../concepts/text-and-fonts/) explains it.
- **Blender's own icons.** All 781 of Blender's SVG icons, rasterized with Blender's nanosvg, in their theme colors.
- **The Blender 5.x theme**, ported from `userdef_default_theme.c`.
- **Panels, the properties navigation bar and many small widget details** ported from Blender, down to the checkmark's shape.
- **Number fields and sliders drag exactly as in Blender:** per-pixel steps, Blender's Ctrl-snapping rules, limits, the drag threshold, and <Kbd>Esc</Kbd> to cancel. See [Blender's widgets](../../concepts/blender-widgets/).

### New components and tools

- **The node editor** (`NodeEditor` and `Node`), ported from Blender's `space_node`: nodes, sockets, bezier links, box select, cutting links and Blender's dot grid.
- **Editor areas, sidebars and middle- and right-button input** for building editor-style tools.
- **Blender's File Browser**, ported from `space_file`, with bookmarks, recent folders, sorting and Blender's keymap. `tkinter.filedialog` and `QFileDialog` now show it; `BUI_FILEDIALOG=native` brings back the system dialogs.

### Native windows on Linux

A native X11 window host, with the same API as on Windows. Wayland sessions run it through XWayland. The C libraries and the Python module now build and pass their tests on Linux.

### JavaScript and React

- **`@blender-ui/native` 0.2.0:** BUI from Node.js and Bun in native windows, with a DOM-like API and signals. BUI runs on its own UI thread, and only changes cross over.
- **`@blender-ui/react` 0.1.0:** a React 19.3 renderer whose hooks (`useState`, `useMemo`, `useEffect` …) are backed by signals. A conformance suite checks each hook against React's own.
- **`bui build`:** standalone executables of about 5 MB with an embedded QuickJS engine, or a Bun executable with `--bun`.

### Rust

- **Components and hooks** in zopra, React or Leptos style: `#[component]`, `use_state`, signals, `Memo`, `Effect` and context.
- **`rsx!` and `view!` markup**, with Tailwind classes as bare attributes and "did you mean" compile errors for typos.
- **Modern CSS:** `calc()` everywhere, every CSS math function, custom properties, CSS Color 4 and 5, Selectors Level 4, `@layer`, `@container`, `@font-face` and more. Layout moved to taffy 0.15.
- **Tailwind CSS v4**, compiled on first use.

### Rendering

- **The GPU renderer** on Direct3D 11, opt-in, drawing the same pixels as the CPU raster.
- **Slug GPU text**, from glyph outlines, switchable with `BUI_SLUG`.
- **Inter embedded** as the default face everywhere, with the portable text engine now the default on Windows too.
- **Parallel canvas rasterisation** on Windows, and many speed-ups across the kit and the Rust crate. For example, a tkinter canvas with 2,000 items and one moving went from 9.4 to 0.08 ms of render time per frame.

### Not in the changelog yet

Some work on `main` is described in the README but doesn't have a changelog entry yet: [Dear ImGui on BUI](../../imgui/cpp/), the OpenGL 3.3 GPU renderer on Linux, the macOS Cocoa window host, and Blender's string search and expression evaluator.

### Fixed

- GPU text read an environment variable on every text run, which pushed the GPU raster from 1.6 to 9.4 ms per frame at 3,000 cells. It now reads it once.
- In Rust, `cx.notify()` inside `WindowHandle::update` didn't re-render that window.

## 0.1.0: the first release

The first release of `blenderui` on PyPI brought the foundations:

- **The C kit:** Blender's UI as a C runtime, with the node tree, Tk's packer and gridder, Blender's interaction (hover, drag grabs, the continuous cursor, menus, tooltips), widget drawing ported from `interface_widgets.cc`, damage-driven rendering, undo and redo, animation, text areas, canvases and scroll views.
- **A native Windows host**, DPI-aware, with vsync'd animation. Other platforms used a Tk window.
- **tkinter syntax:** all 7,846 public names of tkinter and ttk, plus the dialogs and helper modules. Existing apps run unchanged with `blenderui-tk app.py`.
- **Qt syntax:** a subset of Qt's widgets, layouts, signals, `QPainter`, menus and timers.
- **45 Blender components**, from panels and sliders to pie menus, the color picker and editors.
- **Packaging** as `blenderui`, with `import blenderui` as an alias of `bui`.
